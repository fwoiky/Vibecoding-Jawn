# THE 81ST OBJECT

A YOLO11 project that teaches the pretrained 80-class detector to recognise a **Rubik's cube as class 80**.
The cube is **added** to the model. None of the original classes are replaced:

| Model | Classes |
|---|---|
| Stock YOLO11 (`yolo11n.pt`) | 80: ids 0–79 = COCO (person, chair, laptop, cup, …) |
| Trained model (`weights/rubiks_cube_81.pt`) | 81: ids 0–79 = the same COCO classes, id **80 = `rubiks_cube`** |

Everything runs locally from one menu-driven program, `main.py`:

```
============================================================
                    THE 81ST OBJECT
============================================================

1 - Test stock YOLO with webcam
2 - Label your photos
3 - Prepare cube + replay dataset
4 - Verify Labels
5 - Train the new 81-class model
6 - Test the trained model with webcam
7 - Exit

Choose 1-7:
```

---

## 1. Architecture (short version)

```
 photos/ ──(option 2: you drag boxes)──► cube_labels/        MANUAL labels, class 80
                                              │
 replay_images/ ──┐                           │
 (or webcam)      │  option 3                 ▼
                  └──► stock YOLO11 ──► PSEUDO-labels 0-79 ──► dataset/ (80/20 train/val split)
                                                                  │ + data.yaml (81 names)
                                                                  ▼
 yolo11n.pt ──(option 5: widen head 80→81, exact copy)──► yolo11n_81class_start.pt
                                                                  │  fine-tune on dataset/
                                                                  ▼
                                                   weights/rubiks_cube_81.pt  (81 classes)
                                                                  │
                                                     option 6: webcam test
```

* **One detector.** The final model is a single YOLO11 network with an 81-channel classification output.
  It is *not* a separate cube detector running next to the stock one.
* **Replay data against forgetting.** If you trained on cube photos only, the model would slowly forget
  the 80 original classes ("catastrophic forgetting"). Option 3 mixes in *replay* images. The **original
  stock YOLO11** labels them automatically. These labels are **pseudo-labels**: the teacher model's best
  guesses, not verified ground truth. They keep people, laptops, cups and the rest in every training batch.
* **Correct 80 → 81 weight transfer.** In YOLO11 the classification branch's hidden width is
  `max(channels, min(nc, 100))`. For `yolo11n`, changing `nc` from 80 to 81 therefore changes the shape of
  **every** layer in that branch, not only the last one. Ultralytics' normal loading copies only
  same-shape tensors, so the whole class branch would start from random weights. Newer Ultralytics
  versions re-map the last layer by class name, but the hidden layers before it are still random.
  `main.py` does the transfer itself:
  * tensors with the same shape are copied exactly (backbone, neck, box branch);
  * in widened tensors, the old weights are copied into the top-left corner, and connections from the
    new channel into old channels are set to 0;
  * the new cube output row starts at zero weights plus the standard low prior bias.

  The 81-class start model therefore gives **exactly the same results as stock YOLO11** for the 80 old
  classes before training starts. The program checks this and prints `Sanity check ... YES`. Training
  loads it with `Transferred 499/499 items`.

## 3. Installation

**Python version:** use **Python 3.11 or 3.12**. Ultralytics supports 3.8 and newer, but PyTorch wheels
for the newest Python releases sometimes arrive late, and 3.11/3.12 always work.

In PyCharm open **Terminal** (bottom toolbar). Make sure the prompt shows your project's virtual
environment, e.g. `(.venv)`. Then run:

```bash
pip install ultralytics
```

That is the only command you need. Ultralytics installs everything `main.py` imports:
PyTorch, `opencv-python`, NumPy and PyYAML. (`requirements.txt` has the same single line, so
`pip install -r requirements.txt` also works.)

*Optional (NVIDIA GPU on Windows):* `pip` installs a CPU-only PyTorch on Windows. To train on an NVIDIA
GPU, install the CUDA build using the command from <https://pytorch.org/get-started/locally/>.
Training also works on the CPU, just more slowly.

**Internet access:** needed only once, when `yolo11n.pt` (5 MB) is downloaded into `weights/`. If you
are offline, download `yolo11n.pt` from <https://github.com/ultralytics/assets/releases> and copy it into
`weights/`.

## 4. `main.py`

The complete program is [`main.py`](main.py). All settings are at the top:

```python
MODEL_NAME = "yolo11n.pt"      # pretrained YOLO11 weights
EPOCHS = 30
IMAGE_SIZE = 640
BATCH_SIZE = 8
CONFIDENCE_THRESHOLD = 0.35    # webcam display threshold
PSEUDO_LABEL_CONFIDENCE = 0.25 # replay pseudo-label threshold
VALIDATION_FRACTION = 0.20     # 80 % train / 20 % val
FREEZE_LAYERS = 10             # freeze the YOLO11 backbone
PATIENCE = 0                   # early stopping off
OPTIMIZER = "SGD"
LEARNING_RATE = 0.002
WORKERS = 2
DEVICE = None                  # auto; or "cpu", "0", "mps"
CAMERA_INDEX = 0
```

## 6. Putting your cube photos into the project

1. Run `main.py` once (or create the folder yourself). A `photos/` folder appears next to `main.py`.
2. Copy your Rubik's cube photos into `photos/`, e.g. by dragging them onto the folder in PyCharm's
   Project panel. Supported types are `.jpg .jpeg .png .bmp .webp .tif`. **iPhone `.HEIC` photos must be
   exported as JPEG first.**
3. Tips for good results:
   * **30–100 photos** is a good range. Fewer will work, but less reliably.
   * Vary the distance, angle, lighting, background, and which faces are showing. Include some photos
     where you are holding the cube.
   * If possible, take some photos **with the laptop webcam itself**. Option 2 can capture them for you,
     and they match what the model sees in option 6.
4. Your originals are never changed. Option 3 stores resized copies in `dataset/`.

## 7. Running the program in PyCharm

1. **File → Open…** and select the project folder.
2. Set the interpreter: **Settings → Project → Python Interpreter** → add a new *Virtualenv* with
   Python 3.11 or 3.12.
3. Run `pip install ultralytics` in the PyCharm **Terminal**.
4. Right-click `main.py` → **Run 'main'**, or type `python main.py` in the Terminal.
5. The menu appears in the Run/Terminal panel. Type a number and press Enter.
6. When an OpenCV window opens, **click on the window first**. The keyboard keys (Q, N, B, ENTER …) only
   work while that window has focus. Menu choices are typed in the PyCharm console.

Recommended order: **1 → 2 → 3 → 4 → 5 → 6 → 7**.

## 8. Option 2: labeling your photos

The labeling window shows one photo at a time and starts at the first photo that has no label yet.

| Control | Action |
|---|---|
| mouse drag | draw a box around the cube. Draw more boxes if there are several cubes |
| **ENTER** (or SPACE) | accept and save the box(es), then go to the next photo |
| **U** | undo the last box |
| **R** | reset: remove all boxes on this photo (pressing ENTER with no boxes deletes a saved label) |
| **N** | next photo without saving |
| **B** | back to the previous photo (its saved box is shown so you can fix it) |
| **Q** / ESC | quit labeling (your saved work is kept) |

* The bar at the top shows the photo number, the box count and whether the photo is *saved*, *UNSAVED*
  or *not labeled yet*.
* Draw boxes **tightly around the whole cube**.
* Each photo gets a label file in `cube_labels/`, in YOLO format (`class x_center y_center width height`,
  normalised 0–1). For example, `cube_labels/IMG_0042.txt`:
  ```
  80 0.512345 0.433210 0.201000 0.180500
  ```
* Photos you skip are not used for training. You can run option 2 again at any time to continue or
  correct labels.
* Before labeling starts, option 2 asks whether you want to capture extra cube photos with the webcam
  (SPACE = snapshot, A = auto-snapshot every second, Q = done).

## 9. How the replay data works (option 3)

1. **Teacher model:** the original stock `yolo11n.pt` is loaded unchanged.
2. **Replay images:** everything in `replay_images/`. Use everyday scenes: people, chairs, laptops, cups,
   bottles, phones, keyboards, books, backpacks and so on, with **no Rubik's cube in them**.
   If you have fewer than about 50, option 3 offers to **capture them with the webcam**. It shows the
   stock detections live, so you can see what will be labeled. Walk around your room and press A for
   auto-capture. More variety means better protection for the original classes.
3. **Pseudo-labeling:** stock YOLO11 runs on each replay image. Every box with confidence ≥
   `PSEUDO_LABEL_CONFIDENCE` (0.25) is saved as a label with its original class id (0–79). The
   threshold is low on purpose. Any object the teacher is unsure about and leaves unlabeled is taught as
   "background", which pushes the old classes' scores down. In testing, 0.25 retained the original
   classes better than 0.50. Replay images where the teacher found nothing are skipped. You can keep
   them as background images by setting
   `KEEP_EMPTY_REPLAY_IMAGES = True`.
4. **Cube photos get pseudo-labels too:** the person holding the cube, the laptop on the desk and so on
   are also labeled by the teacher. Without this, the training would learn that those objects are
   "background". If the teacher puts a box on the cube itself (e.g. calls it a "clock"), that box is
   removed, because it overlaps your manual cube box.
5. **Your cube boxes** from `cube_labels/` are added with class id **80**.
6. **Deterministic 80/20 split:** each file goes to train or val based on a hash of its file name, so
   repeated runs give the same split and no image is ever in both sets. Cube and replay images are split
   separately, so both appear in train and in val.
7. `dataset/data.yaml` (81 names) and `dataset/label_info.json` are written. The summary shows how many
   **manual** boxes and how many **pseudo** boxes were made, and which of the 80 classes are represented.

**Be honest about pseudo-labels.** They come from a model, not a human. They include some mistakes and
miss some objects. They are good enough to *remind* the network of the old classes, but they are not
ground truth. Validation scores for classes 0–79 are measured against these pseudo-labels, so treat
them as approximate. Classes that never appear in your replay images get no replay protection.

### Option 4: verify labels

The viewer steps through every dataset image and draws the labels back onto it:

* **magenta** box `rubiks_cube (manual)`: your label
* other colours, e.g. `person 0.87 (pseudo)`: a pseudo-label with the teacher's confidence

| Key | Action |
|---|---|
| **N** / SPACE | next image |
| **B** | previous image |
| **C** | jump to the next cube image |
| **Q** / ESC | quit |

Before the viewer opens, every label file is checked (5 numbers per line, values 0–1, class ids 0–80).
Any problem is printed in the console and shown in red in the window.
To fix a cube box, go back to option 2 and then run option 3 again. To remove a bad replay image, delete
it from `replay_images/` and run option 3 again.

## 10. How training works (option 5)

1. **Checks:** `data.yaml` exists and has 81 names that exactly match the stock COCO names plus
   `rubiks_cube`. The training set must contain cube labels (class 80) and replay labels (0–79), and
   the validation set must not be empty.
2. **Build the 81-class start model:** the head is widened as described in section 1 and saved as
   `weights/yolo11n_81class_start.pt`. A sanity check confirms that it detects the 80 old classes
   exactly like stock YOLO11.
3. **Fine-tune** with the Ultralytics API:
   ```python
   YOLO("weights/yolo11n_81class_start.pt").train(
       data="dataset/data.yaml", epochs=30, imgsz=640, batch=8,
       optimizer="SGD", lr0=0.002, freeze=10, patience=0, ...)
   ```
   * `freeze=10` freezes the YOLO11 backbone (layers 0–9). Its general visual features stay fixed. The
     neck and head learn the cube, and the replay data keeps them good at the 80 old classes.
   * Early stopping is off (`PATIENCE = 0`). At first the new class barely registers in the overall
     validation score, so Ultralytics would stop training too early.
   * `SGD` at `lr0 = 0.002`: the `auto` choice (AdamW with a tiny learning rate) never learned the new
     class in 30 epochs. The Ultralytics default of 0.01 learned it but forgot more of the old classes.
     See the table below.
4. **Save:** `runs/detect/rubiks_cube_81/weights/last.pt` is copied to **`weights/rubiks_cube_81.pt`**.
   The final-epoch model is used, not Ultralytics' `best.pt`. `best.pt` is chosen by validation score,
   and most validation labels are pseudo-labels *made by the stock model*, so the untouched epoch-1 model
   always looks "best" even though it can't detect the cube yet. The program reloads the saved file,
   confirms it has 81 classes with class 80 = `rubiks_cube`, and prints the cube's validation AP.

### What the settings were based on

These defaults were chosen by testing the whole pipeline. The test used 96 COCO images as replay
images, pseudo-labeled by this program, plus 13 synthetic Rubik's-cube photos. Each setting was trained
for 30 epochs on a CPU at 320 px. Forgetting was measured on **32 separate COCO images with real
human labels**, which were never used for training:

| Setup | Cube AP50 | Original 80 classes, held-out mAP50-95 (stock = 0.426) |
|---|---|---|
| Ultralytics' built-in 80→81 loading (no head widening), SGD 0.01 | 0.995 | 0.069, almost everything forgotten |
| Widened head, SGD 0.01, pseudo-label conf 0.50 | 0.995 | 0.236 |
| Widened head, `optimizer="auto"` | 0.000, cube never learned | 0.388 |
| Widened head, SGD 0.002, pseudo-label conf 0.50 | 0.863 | 0.383 |
| **Widened head, SGD 0.002, pseudo-label conf 0.25 (defaults)** | **0.995** | **0.386, about 91 % of stock kept** |

Some forgetting is unavoidable with a small pseudo-labeled replay set. More replay images, especially
ones that show the objects you care about, keep more of the original performance. The cube numbers come
from synthetic cube images, so your real results will depend on your photos.

**Time:** on a laptop CPU, expect roughly 1–3 minutes per epoch for about 200 images at 640 px. To do a
quick test run first, lower `EPOCHS` (e.g. 5) or `IMAGE_SIZE` (e.g. 416).

## 11. Testing the final 81-class model (option 6)

Option 6 loads `weights/rubiks_cube_81.pt` and opens the webcam. Each object gets a box labeled with
its class name and confidence, and the top-left panel lists the current detections, for example:

```
laptop        0.86
rubiks_cube   0.78      <- shown in magenta
person        0.91
```

Hold the cube next to a laptop, cup or phone: all of them should be detected by **the same model**.
Press **Q** (with the video window focused) to return to the menu. Compare it with option 1, the
"before" demo, where the stock model has no name for the cube.

If the cube is detected only weakly, add more varied cube photos (especially webcam ones), label them,
and run options 3 and 5 again. You can also lower `CONFIDENCE_THRESHOLD`.

## 12. Troubleshooting

| Problem | Fix |
|---|---|
| `No module named 'ultralytics'` / `cv2` | Run `pip install ultralytics` in the **PyCharm Terminal**, and check that PyCharm's interpreter is the same virtual environment. |
| `cv2.imshow ... The function is not implemented` | You have the headless OpenCV. Run `pip uninstall -y opencv-python-headless opencv-python` then `pip install opencv-python`. |
| Webcam doesn't open / black window | Close Zoom/Teams/browser tabs that use the camera. Windows: *Settings → Privacy → Camera → allow desktop apps*. macOS: *System Settings → Privacy & Security → Camera → PyCharm*, then restart PyCharm. Try `CAMERA_INDEX = 1`. |
| Keys (Q, N, ENTER …) do nothing | Click on the OpenCV window first so it has keyboard focus. |
| `yolo11n.pt` download fails | You are offline or behind a firewall. Download it from <https://github.com/ultralytics/assets/releases> and put it in `weights/`. |
| "No photos found" | Put `.jpg`/`.png` files directly inside `photos/` (not in a subfolder). Convert `.HEIC` to JPEG. |
| "No labeled cube photos were found" | Run option 2 and press ENTER on each photo to save the box. |
| "The replay dataset is empty" | Add everyday photos to `replay_images/` or let option 3 capture them with the webcam. |
| "Training cannot start …" | Read the message: it tells you which option to run (usually 2 or 3). |
| Training error mentioning *workers* / *pickle* on Windows | Set `WORKERS = 0` at the top of `main.py`. |
| `CUDA out of memory` | Lower `BATCH_SIZE` (e.g. 4) or `IMAGE_SIZE` (e.g. 480). |
| Training is very slow | That's normal on a CPU. Lower `EPOCHS`/`IMAGE_SIZE`, or use an NVIDIA GPU. |
| Cube not detected in option 6 | Add more (webcam) cube photos with varied angles and backgrounds, re-label, re-run 3 and 5. Lower `CONFIDENCE_THRESHOLD` to 0.25. |
| An original class got worse | Add replay images that contain that object, re-run 3 and 5. |
| Ultralytics prints "downloading yolo26n.pt for AMP checks" | Normal on NVIDIA GPUs: it's a one-time self-test file and isn't used for training. |
| Option 6 says "No trained model found" | Run option 5 first. It saves `weights/rubiks_cube_81.pt`. |
| Moved the project folder | Run option 3 again (`data.yaml` stores the absolute dataset path). |
